# Changelog

All notable changes to Thunder Dynamics are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [v1.2.3] - 2026-10-16
### Features
- `dyn_builder`: `M`, `Cdq`, `G` by recursive Newton-Euler (RNEA) or composite rigid body algorithm (CRBA), besides Lagrange, selected with `dynamics_method` (`auto`, `rnea`, `crba`, `lagrange`). `auto` takes the cheapest expression.
- `dyn_builder`: matrix `C` from the modified RNEA (Niemeyer-Slotine), selected with `C_method` (`auto`, `rnea`, `christoffel`).
- `dyn_builder`, `reg_builder`: new functions `tau` (`M ddq + C dq + G`) and `tau_r` (`M ddqr + C dqr + G`), by one-pass RNEA.
- `reg_builder`: dynamic regressors (`Yr`, `Y`, `reg_M`, `reg_C`, `reg_G`) from the modified RNEA, selected with `regressor_method` (`rnea`, `lagrange`). It works without `dyn_builder`, and the initial `par_REG` can be set in its configuration.
- `kin_builder`: Jacobians from the motion subspaces `S_JOINT_<type>` of the joints. For a joint type without `S_JOINT`, it is derived from `T_JOINT`.
- Generators: a function can be left out of the generated code with `functions: {<name>: {ignore: true}}`.
- Automatic tests with CTest (`-DWITH_TESTS=ON`), including a comparison of kinematics, dynamics and regressors with Pinocchio.
- Documentation of every plugin in `docs/plugins/`.

### Changed
- **Breaking:** `dyn_builder` adds `C_std`, `J_cm_<i>` and the time derivatives of `M`, `C`, `G` only when asked, with `compute_C_std`, `compute_J_cm`, `compute_derivatives` (all `false` by default). Before, they were always generated.
- **Breaking:** `J_<name>_dot` and `J_<name>_ddot` are added only with `kin_builder: compute_derivatives: true` or `derivatives: true` on the frame. `J_<name>_pinv` is now added for every named (`available`) frame.
- The default dynamics method is `auto` instead of Lagrange: same values, smaller generated code.
- `dh_loader`: a node `link<n>` is added for the body moved by the last DH row, before the end-effector frame. The indices of the end-effector frames change.
- `soft_loader`: the parameters of each elastic joint are taken by joint name; a missing entry is an error.
- `Config` with a dict: relative paths (e.g. `urdf_path`) and the modules of `py.` plugins are resolved from the current working directory.
- Generated Python package: link-time optimization is disabled (it needed more than 16 GB of RAM on large robots, with no speed gain). An installed yaml-cpp (>= 0.8) is used if found.
- Docker image: `numpy` and `pydantic` are installed.

### Fixed
- `urdf_loader`: some joint origins were converted to a wrong frame, when their rotation is singular for the thunder `rpy` convention (pitch ±90°, e.g. `rpy="${pi/2} ${pi/2} ${-pi/2}"`).
- `urdf_loader`: the inertia is rotated from the `<inertial><origin>` frame to the link frame.
- `urdf_loader`: the `<symbolic_kinematics>` mask of a URDF joint applies to the origin of that joint.
- `urdf_loader`: wrong parent of the branch nodes in trees.
- `dh_loader`: mismatch between links and joints.
- `soft_loader`, `soft_builder`: mismatch between `q` and `x` when the robot has non-elastic joints.
- `Robot::set` with only the symbolic entries wrote the wrong entries.
- Generated Python bindings: missing `pybind11/stl.h`.
- `thunder gen` returns 0 on success.
- Documentation: getter names in the README, the C++ plugin example, `run_pipeline` (which does not exist) replaced by `Config(...).execute(...)`.

## [v1.1.2] - 2026-10-06
### Features
- Add ROS Server Generator to plugins: `ros_server_generator` creates a ROS 2 C++ package around the robot generated by `robot_generator`. Robot functions and runtime parameters are exposed as services (`services`, all by default) and topics (`topics`), and parameters can be updated from topics (`inputs`). The node runs at `frequency` Hz, optionally with real-time scheduling (`real_time`). Messages use the package's own `Float32Array` message, and the package name is the robot name in lowercase.
- `reg_builder`: new standard regressor `Y`, besides the Slotine-Li regressor `Yr`.
### Fixed
- Fix compatibility with ROS 1 noetic for thunder generated code: the generated class uses `Eigen::Matrix<double,n,1>` instead of `Eigen::Vector`, which requires Eigen 3.4. Parameters are initialised in the constructor of the class.

## [v1.0.2] - 2026-10-01
### Fixed
- Solve problem on soft_loader plugin in elastic joint loading: the elastic flags `isSoftJoint` are now one per joint variable, skipping fixed joints. With fixed joints in the chain, they were assigned to the wrong joints.
- Binaries built in the build folder find the CasADi library without being installed (`BUILD_RPATH` to the CasADi library folder).

## [v1.0.1] - 2026-09-29
### Fixed
- Update the CasADi build dependency to version 3.8.0. The Docker image builds CasADi 3.8.0 and yaml-cpp 0.9.0 instead of the latest commit of their default branch.

## [Thunder Dynamics v1.0.0] - 2026-08-03
Starting point of the changelog. First release of the plugin architecture:
- Loaders: `kin_loader`, `dh_loader`, `urdf_loader`, `dyn_loader`, `soft_loader`.
- Builders: `kin_builder`, `dyn_builder`, `reg_builder`, `soft_builder`, and `example_builder` as a template.
- Generators: `robot_generator`, which generates the C code of the functions with CasADi, the `thunder_<robot>` C++ class, and optionally Python bindings and CasADi files.
- Plugins written in Python (`py.<module>.<Class>`), and the `thunder_core` Python package to run the pipeline from Python.
- `thunder` command line: `thunder gen <robot>.yaml` and `thunder plugin list`.
