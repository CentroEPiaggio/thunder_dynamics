# Robot Generator Plugin

`robot_generator` turns the functions built by the builders into code: a C library generated by CasADi and a C++ class, `thunder_<robot>`, that holds the parameters and calls it. Optionally it also prepares Python bindings and saves the CasADi functions. Run it after all the builders.

```yaml
pipeline:
  loaders: [urdf_loader]
  builders: [kin_builder, dyn_builder]
  generators: [robot_generator]

robot_generator:              # all keys optional
  gen_robot: true             # thunder_<robot> class (default true)
  gen_python: false           # Python bindings (default false)
  gen_casadi: false           # .casadi files (default false)
  copy_gen: false             # copy into src/thunder_robot_test (default false)
```

`<robot>` is the robot name: with the CLI, the name of the YAML file, or the one given with `thunder gen -n <name>`.

## Output

Everything is written to `<robot>_generatedFiles/`, in the working directory.

| File | When | Content |
| --- | --- | --- |
| `<robot>_gen.h`, `<robot>_gen.cpp` | always | C code of every robot function, generated by CasADi |
| `thunder_<robot>.h`, `thunder_<robot>.cpp` | `gen_robot` or `gen_python` | The wrapper class |
| `<robot>_conf.yaml` | `gen_robot` or `gen_python` | The configuration used to generate the robot |
| `<robot>_par.yaml` | `gen_robot` or `gen_python` | Values of the parameters, readable with `load_par()` |
| `casadi_functions/<name>.casadi` | `gen_casadi` | Each function serialised by CasADi, to load with `casadi.Function.load()` |
| `CMakeLists.txt`, `pyproject.toml`, `README.md`, `thunder_<robot>_py/` | `gen_python` | Python package, built with `pip install .` from the output directory |

The Python files are copied from the templates in `/usr/share/thunder_dynamics/templates/`, installed with thunder. With `gen_python`, `thunder_<robot>.cpp` also contains the pybind11 bindings of the class, compiled when `ENABLE_PYBIND11` is defined.

`copy_gen` copies the C++ files and the two YAML files into `src/thunder_robot_test/` (`include/`, `src/`, `robots/`), to test the robot there. The repository is found three levels above the working directory when it is called `build`, and at `/home/thunder_dev/thunder_dynamics/` (the dev container) otherwise.

## The `thunder_<robot>` class

```cpp
#include "thunder_franka.h"

thunder_franka robot;               // parameters at the values of the configuration
robot.load_par("franka_par.yaml");  // or load them from a file
robot.set_q(q);
robot.set_dq(dq);
Eigen::Matrix<double,8,8> M = robot.get_M();
Eigen::Matrix<double,6,8> J = robot.get_J_EE();
```

| Member | Description |
| --- | --- |
| `set_<par>(value)`, `get_<par>()` | One pair for each parameter or variable with at least one symbolic entry (`q`, `dq`, `par_DYN`, ...). The vector holds only the symbolic entries, in order: the numeric ones are constants in the code |
| `get_<function>()` | One for each robot function (`get_M()`, `get_T_w_EE()`, ...). It evaluates the function with the current parameters and returns a fixed-size `Eigen::Matrix`. Functions with explicit arguments, such as the joint templates, take them as arguments |
| `save_par(file, list = {})`, `load_par(file, list = {})` | Write or read the parameters to or from a YAML file, all of them or those in `list`. Return 1 on success |
| `robotName`, `numJoints`, `ndof`, `jointsName`, ... | The robot properties, as constants |

Each `get_<function>()` evaluates its function from scratch: calling several of them recomputes their common parts. The work buffers are `thread_local`, so different threads can use the class at the same time on different objects.

The class needs Eigen and yaml-cpp.
